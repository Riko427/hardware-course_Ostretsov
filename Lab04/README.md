# Изменяем количество потоков

| Количество потоков | Примерная нагрузка CPU |
| -----------------: | ---------------------: |
|                  1 |                    17% |
|                  2 |                    34% |
|                  4 |                    63% |
|                  8 |                   100% |
|                 16 |                   100% |

Вывод: при увеличении количества одновременно работающих потоков нагрузка на CPU увеличивается. После некоторого количества потоков дальнейшее увеличение не обязательно продолжает заметно повышать загрузку, так как для процесса было использовано достаточное количество потоков.

# Итоговый вопрос

Потому что Environment.ProcessorCount показывает количество логических ядер, а не физических.

# Контрольные вопросы

1. Что показывает Environment.ProcessorCount?

Ответ: Количество логических ядер.

2. Чем физическое ядро отличается от логического процессора?

Ответ: Физические ядро можно потрогать, а логическое нет.

3. Почему увеличение количества потоков может увеличить загрузку CPU?

Ответ: Потому что увеличивается количество задействованных логических ядер и нагрузка на процессор данным процессом становится больше.

4. Почему после некоторого количества потоков загрузка не обязательно
   продолжает расти?

Ответ: После некоторого количества потоков дальнейшее увеличение не обязательно продолжает заметно повышать загрузку, так как для процесса было использовано достаточное количество потоков.

5. Почему частота процессора может изменяться во время работы?

Ответ: Процессоры автоматически изменяют свою частоту в зависимости от нагрузки.

# Итоговый вывод

Система использует разделение физических ядер на логические ради многозадачности и оптимизации процессов. Таким образом один процесс может протекать в одном потоке, когда другой выполняется во втором потоке. Если направить на один процесс несколько потоков, то на остальные останется меньше или займётся ровно столько, сколько нужно для процесса.
