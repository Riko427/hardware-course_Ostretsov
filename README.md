1. "dotnet run" делает две вещи сразу: собирает проект и запускает его, а "dotnet build" запускает .dll проекта.
2. Появляются файлы с одинаковыми иминами "Lab01", но с разными расширениями, а именно:(.dll, .exe, .pdb, .deps.json, .runtimeconfig.json). 
В Lab01.dll лежит моя программа в виде IL-байткода.
В Lab01.exe лежит небольшой исполняемый «запускатель» под Windows, который находит Runtime и передаёт ему .dll.
В Lab01.pdb лежат символы отладки, которые нужны для пошаговой отладки и красивых сообщений об ошибках.
В Lab01.deps.json лежит список зависимостей.
В Lab01.runtimeconfig.json находится информация на какой версии .NET запускать программу.
3. Сначала компилятор переводит текст программы в промежуточный язык IL. Затем, уже при запуске программы, JIT-компилятор, входящий в состав .NET Runtime,переводит IL в инструкции моего процессора. Всё это нужно, чтобы преобразовать текст с кодом в понятный для процессора машинный код.
4. .gitignore нужен, чтобы не загружать репозиторий ненужными файлами. Ничего глобального, просто репозиторий будет занимать больше места.
5. Для фамилии - string,
для возраста - int,
для среднего балла - double,
для признака «студент отчислен / не отчислен» - bool.
6. Количество логических ядер в моём процессоре. Количество логических ядер в процессоре ноутбука соседа. Разные процессоры.
